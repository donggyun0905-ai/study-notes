# ch13-1. 파일 업로드 — COS 라이브러리

---

## 1. 왜 특별한 라이브러리가 필요한가

일반 폼은 `enctype`이 기본값(`application/x-www-form-urlencoded`)이라 텍스트만 보낼 수 있습니다. **파일을 보내려면 `multipart/form-data`**로 바꿔야 하는데, 이 형식은 `request.getParameter()`로 못 읽습니다 — 파일 바이너리와 텍스트 필드가 뒤섞인 복잡한 구조라서, 이걸 파싱해주는 전용 라이브러리가 필요합니다. 그게 **COS**(`com.oreilly.servlet`)입니다.

```jsp
<form method="post" action="fuploadProc.jsp" enctype="multipart/form-data">
    <input type="file" name="upFile">
</form>
```

## 2. 라이브러리 설치 — Maven Central에 없는 jar 다루는 법

`cos-jakarta.jar`(Tomcat 10용으로 포팅된 버전)는 Maven Central에 없습니다. 이런 jar는 **로컬 저장소에 직접 설치**해서 씁니다.

```powershell
mvn install:install-file -Dfile=cos-jakarta.jar `
  -DgroupId=com.oreilly.servlet -DartifactId=cos-jakarta -Dversion=1.0 -Dpackaging=jar
```

```xml
<!-- pom.xml -->
<dependency>
  <groupId>com.oreilly.servlet</groupId>
  <artifactId>cos-jakarta</artifactId>
  <version>1.0</version>
</dependency>
```

> **자주 하는 실수** — jar를 `src/main/webapp/` 최상위 같은 곳에 그냥 넣으면 **브라우저로 다운로드되는 정적 파일** 취급됩니다. 자바 코드가 컴파일할 때 쓸 수 있는 위치가 아닙니다. 위처럼 pom.xml로 관리해야 컴파일·배포 둘 다 됩니다.

> **jar를 새로 추가했으면 톰캣 재시작 필수** — 이미 떠있는 톰캣은 시작할 때 만든 클래스패스를 그대로 씁니다. `WEB-INF/lib`에 새 jar가 생겨도 재시작 전엔 `NoClassDefFoundError`류 에러가 납니다.

## 3. 업로드 폼 → 처리 흐름

```
fupload.jsp (또는 fileSelect.jsp)  →  fuploadProc.jsp  →  viewPage.jsp(테스트용) / flist.jsp
   (파일 선택 폼)                      (실제 저장 처리)         (결과 확인)
```

### fupload.jsp — 입력 폼
```jsp
<form method="post" action="fuploadProc.jsp" enctype="multipart/form-data">
    <input type="file" name="upFile">
    <input type="button" value="파일업로드" onclick="check()">
</form>
<script>
    function check() {
        frm = document.forms[0];
        if(frm.upFile.value == 0){          // 파일 선택 안 했을 때
            alert("파일을 선택하세요.");
            return;
        }
        frm.submit();
    }
</script>
```

## 4. `MultipartRequest` — 핵심 클래스

```java
MultipartRequest multi = new MultipartRequest(
    request,                        // 원본 요청
    SAVEFOLDER,                     // 저장할 폴더 경로 (미리 존재해야 함!)
    MAXSIZE,                        // 최대 크기 (바이트)
    ENCODING,                       // 인코딩
    new DefaultFileRenamePolicy()   // 같은 이름 파일 있으면 자동으로 번호 붙여 rename
);
```

**`MultipartRequest` 객체가 생성되는 그 순간, 이미 서버에 파일이 저장됩니다.** (생성자 안에서 파일을 읽어서 씀) — "만들고 나서 나중에 저장"이 아니라 "만드는 게 곧 저장"입니다.

### 자주 쓰는 조회 메소드

| 메소드 | 반환 | 용도 |
|---|---|---|
| `multi.getParameter("name")` | `String` | 일반 텍스트 필드 값 |
| `multi.getFilesystemName("upFile")` | `String` | **실제 저장된 파일명** (rename 정책 적용된 이름) |
| `multi.getContentType("upFile")` | `String` | MIME 타입 (`text/plain` 등) |
| `multi.getFile("upFile")` | `java.io.File` | 저장된 파일 객체 (크기 확인 등에 사용) |

> **타입 헷갈리지 않기** — `getFile()`은 `File`, `getFilesystemName()`은 `String`입니다. DB에 저장할 "파일명 문자열"이 필요하면 `getFilesystemName()`, 파일 크기(`.length()`)가 필요하면 `getFile()`을 써야 합니다. (실제로 이 둘을 헷갈려서 컴파일 에러 난 적 있음 — 아래 "겪은 버그" 참고)

### 폴더는 미리 있어야 함
COS는 저장 폴더를 자동으로 안 만들어줍니다. `SAVEFOLDER` 경로가 없으면 예외가 납니다 — 미리 `mkdir`로 만들어두거나, 코드에서 `new File(SAVEFOLDER).mkdirs()`로 확인 후 생성해야 합니다.

## 5. 저장 처리 — FileloadMgr.uploadFile()

```java
public class FileloadMgr {
    public final static String SAVEFOLDER = "C:/Jsp/myapp/src/main/webapp/ch13/storage/";
    public final static String ENCODING = "UTF-8";
    public final static int MAXSIZE = 1024*1024*50;   // 50mb

    public void uploadFile(HttpServletRequest request){
        Connection con = null;
        PreparedStatement pstmt = null;
        try {
            MultipartRequest multi = new MultipartRequest(request, SAVEFOLDER, MAXSIZE, ENCODING, new DefaultFileRenamePolicy());
            File f = multi.getFile("upFile");
            long size = f.length();
            String upFile = multi.getFilesystemName("upFile");

            con = pool.getConnection();
            String sql = "insert tblFileload (upFile,size) values (?,?)";
            pstmt = con.prepareStatement(sql);
            pstmt.setString(1, upFile);
            pstmt.setLong(2, size);
            pstmt.executeUpdate();
        } catch (Exception e) {
            e.printStackTrace();
        } finally {
            pool.freeConnection(con, pstmt);
        }
    }
}
```

**DB 테이블 (`tblfileload`)**
```sql
CREATE TABLE tblfileload (
    num    int NOT NULL AUTO_INCREMENT PRIMARY KEY,
    upFile char(50) NOT NULL,
    size   int
);
```

## 6. 한글 파라미터 깨짐 — COS의 알려진 함정

`getParameter()`로 읽는 **일반 텍스트 필드**(`user`, `title` 등)는, 생성자에 `ENCODING="UTF-8"`을 줘도 한글이 깨집니다. (ch12 쿠키 노트에서 본 것과 다른, COS 라이브러리 자체의 버그성 동작)

```java
// 깨짐
String user = multi.getParameter("user");

// 고침: ISO-8859-1로 잘못 읽힌 걸 원래 바이트로 되돌린 뒤 UTF-8로 재해석
String user = new String(multi.getParameter("user").getBytes("8859_1"), "UTF-8");
```

> **`getFilesystemName()`(파일명)은 이 문제가 없습니다** — encoding 인자가 파일명에는 정상 적용되어서, 파일명은 그냥 써도 됩니다. **일반 텍스트 필드만** 이 변환이 필요합니다.

이 문제를 테스트할 때 `curl -F`로 한글을 보내면 **윈도우 터미널 자체가 한글 인자를 깨뜨려 보낼 수 있어서** 혼란스러울 수 있습니다 — 실제 브라우저 폼 제출은 항상 정확한 UTF-8을 보내므로 문제없습니다.

## 7. 겪은 버그 모음

| 위치 | 문제 | 원인 |
|---|---|---|
| `FileloadMgr.uploadFile()` | `String upFile = multi.getFile(...)` 컴파일 에러 | `getFile()`은 `File` 반환인데 `String`에 대입 시도 |
| 〃 | `f.length()`에서 `f` 못 찾음 | `File f = multi.getFile(...)` 선언 자체가 빠짐 |
| `viewPage.jsp` | 한글 파라미터 깨짐 | 위 6번 항목 — `getBytes("8859_1")` 변환 안 함 |
| 배포 후 500 에러 | `resolves to a package` | 새로 추가한 `cos-jakarta.jar`를 이미 떠있는 톰캣이 못 읽음 → 재시작 필요 |

## 8. 이렇게 써야 한다 — 업로드 처리 템플릿

```java
MultipartRequest multi = new MultipartRequest(request, SAVEFOLDER, MAXSIZE, ENCODING, new DefaultFileRenamePolicy());

String text  = new String(multi.getParameter("필드명").getBytes("8859_1"), "UTF-8");  // 텍스트는 재인코딩
String fname = multi.getFilesystemName("파일필드명");                                    // 파일명은 그대로
File   f     = multi.getFile("파일필드명");
long   size  = (f != null) ? f.length() : 0;   // null 체크 (파일 선택 안 했을 경우 대비)
```

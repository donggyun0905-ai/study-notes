## 2. 빌드 명령 — 뭘 언제 쓰나 (중요)

| 명령 | 하는 일 | 결과물 | 언제 |
|---|---|---|---|
| `mvn compile` | `.java` → `.class` 컴파일만 | `target/classes/` | 자바 문법만 확인할 때 |
| `mvn package` | 컴파일 + **웹앱 조립 + WAR 생성** | `target/classes/`, **`target/myapp/`**, `target/myapp.war` | 배포하거나 실행할 때 |
| `mvn clean` | `target/` 폴더 **통째로 삭제** | (아무것도 안 만듦) | 단독으로 쓰지 말 것 |
| `mvn clean package` | 싹 지우고 처음부터 다 만들기 | 위 package와 동일 (깨끗한 상태) | **평소엔 이거** |

> **`mvn clean compile` 은 위험** — `target/` 을 지운 뒤 `.class`만 만들고, 배포용 `target/myapp` 폴더는 안 만듭니다. IntelliJ 톰캣이 `target/myapp`을 배포 대상으로 보고 있으면, 그 폴더가 사라져서 배포가 깨집니다. (아래 3번 사고)

## 3. 사고 분석 — "배포 성공"이라는데 전부 404

### 증상
IntelliJ가 "Artifact deployed successfully" 라고 뜨는데, 모든 페이지가 404.

### 원인 추적
톰캣 로그(`.../tomcat/<id>/logs/catalina.*.log`)에서:
```
SEVERE ... 배치 descriptor [...myapp.xml]을(를) 배치하는 중 오류 발생
Caused by: java.lang.IllegalArgumentException:
    The main resource set specified [C:\Jsp\myapp\target\myapp]
    is not a directory ... (it does not exist)
```

- IntelliJ 톰캣의 컨텍스트 설정: `<Context path="/myapp" docBase="C:\Jsp\myapp\target\myapp" />`
- 즉 `/myapp` 은 `target\myapp` 폴더를 바라봄
- 그런데 `mvn clean compile` 을 돌려서 `target\myapp` 이 **삭제된 상태**였음
- → `/myapp` 컨텍스트가 시작 실패 → **그 아래 모든 URL이 404**
- "배포 성공"은 IntelliJ가 파일을 등록만 했다는 뜻. 톰캣 컨텍스트가 실제로 떴는지는 별개.

### 해결
1. `mvn clean package` — `target/myapp` 다시 생성
2. IntelliJ에서 `jsp` 실행 **정지 → 다시 실행**

### 재발 방지 — `jsp` 실행 구성에 빌드 단계 추가
`jsp` 실행 구성엔 원래 "실행 전 빌드" 단계가 **없었음** (그래서 낡은/없는 상태 그대로 배포됨).

1. Run → Edit Configurations → `jsp`
2. 맨 아래 **Before launch** → **`+`** → **Build Artifacts** → `myapp:war exploded` 체크
3. Apply → OK

이제 `jsp` 실행할 때마다 IntelliJ가 `target/myapp` 을 자동으로 다시 만듦.

### 교훈
- 터미널 빌드는 `mvn clean package` (`compile` 단독 X)
- IntelliJ 실행 구성에 "Before launch → Build Artifacts" 는 필수

## 4. WAR 파일 배포 (배포 수업)

`.war` = 웹앱을 통째로 압축한 파일 (내용물은 `.zip`과 동일 구조).

### WAR 내부 구조
```
myapp.war
├── index.jsp, ch06/, ch07/, ch09/, css/   ← webapp 폴더 내용이 그대로 최상위
├── META-INF/context.xml
└── WEB-INF/                ← 브라우저 직접 접근 불가 (보안)
    ├── web.xml
    ├── classes/            ← 컴파일된 .class (서블릿, DAO, DTO)
    └── lib/                ← 의존 jar (JSTL, mysql-connector, ojdbc11 ...)
```

### 만드는 법
```powershell
cd C:\Jsp\myapp
mvn clean package
# → target\myapp.war 생성
```

### 배포하는 법 3가지

| 방법 | 절차 | 톰캣 재시작 |
|---|---|---|
| **1. webapps에 복사** | 톰캣 끄기 → `webapps\`에 `myapp.war` 복사 → 톰캣 켜기 (자동으로 압축 풀림) | 필요 |
| **2. Manager 웹 업로드** | `tomcat-users.xml`에 `manager-gui` 계정 추가 → `http://localhost/manager/html` → WAR 파일 선택 → Deploy | 불필요 |
| **3. Context 서술자** | `conf/Catalina/localhost/myapp.xml`에 `<Context docBase="...\target\myapp.war"/>` | 필요 |

> **⚠️ 톰캣이 켜진 상태에서 `webapps` 안 파일을 지우면 안 됨** — 톰캣이 파일을 붙잡고 있어서(Windows 파일 잠금) 충돌로 톰캣이 죽을 수 있음. **끄고 → 바꾸고 → 켜기** 순서.

## 5. 라이브러리 추가 (Maven 방식)

`WEB-INF/lib`에 jar를 **직접 넣지 말 것.** Maven 프로젝트는 `pom.xml`에 적으면 빌드 시 자동으로 WAR에 포함됨. 직접 넣으면 버전이 다른 게 2개 들어가서 충돌.

```xml
<dependency>
  <groupId>com.oracle.database.jdbc</groupId>
  <artifactId>ojdbc11</artifactId>
  <version>23.9.0.25.07</version>
</dependency>
```

추가 후 → IntelliJ **Maven 창(오른쪽 세로탭) → 🔄 Reload All Maven Projects** → 끝.
("Reload"는 뭘 껐다 켜는 게 아니라 pom.xml을 다시 읽는 동작)

## 6. Oracle 접속 (ch09)

### URL 문법 — SID vs 서비스명

| 문법 | 예시 | 구분자 |
|---|---|---|
| SID | `jdbc:oracle:thin:@localhost:1521:xe` | 콜론 `:` |
| 서비스명 | `jdbc:oracle:thin:@localhost:1521/xe` | 슬래시 `/` |

- Oracle 23ai Free는 SID가 `free`, `xe`는 서비스명 → `:xe`(SID 문법)로는 접속 안 됨
- **해결책 A**: URL을 `/xe` 로
- **해결책 B**: `listener.ora`에 `USE_SID_AS_SERVICE_LISTENER = ON` 추가 후 리스너 재시작 → `:xe` 도 통함 (원본은 `listener.ora.bak` 백업됨)

### 리스너 재시작
```powershell
# 관리자 PowerShell
Restart-Service OracleOraDB23Home1TNSListener
```

### 접속 확인 (sqlplus)
```powershell
& "C:\app\dita_810\product\23ai\dbhomeFree\bin\sqlplus.exe" "c##hr/1234@localhost:1521/xe"
```

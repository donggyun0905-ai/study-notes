# ch09-6. 서블릿으로 처리하기 — `TeamDeleteServlet`

JSP(`teamDelete.jsp`)로 하던 삭제 처리를, 같은 일을 하는 **서블릿**으로도 만들어본 예제.

---

## 1. JSP로 처리 vs 서블릿으로 처리 — 같은 일, 다른 그릇

| | `teamDelete.jsp` | `TeamDeleteServlet.java` |
|---|---|---|
| 정체 | HTML 파일처럼 보이는 텍스트 파일 | 순수 자바 클래스 |
| URL | 파일 경로 그대로 (`/ch09/teamDelete.jsp`) | `@WebServlet`으로 **직접 지정** (`/ch09/teamDelete`) |
| 변환 | 톰캣이 요청마다 자바로 변환(필요시) | 이미 자바라서 변환 없음, 미리 컴파일 |
| 화면 출력 | HTML을 섞어 쓰기 편함 | `response.getWriter()`로 직접 찍어야 함(불편) |

이 예제처럼 **"화면 없이 로직만 처리하고 바로 redirect"** 하는 경우는 서블릿이 더 "정석"입니다 — 애초에 HTML을 안 섞으니까요.

## 2. 서블릿 매핑 — `@WebServlet`

```java
@WebServlet("/ch09/teamDelete")
public class TeamDeleteServlet extends HttpServlet {
    protected void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        TeamMgr mgr = new TeamMgr();
        int num = 0;
        if(request.getParameter("num") != null
                && MUtil.isNumeric(request.getParameter("num"))){
            num = MUtil.parseInt(request, "num");
            mgr.deleteTeam(num);
        }
        response.sendRedirect("teamList.jsp");
    }
}
```

- `web.xml`에 `<servlet>`/`<servlet-mapping>`을 안 써도, `@WebServlet("경로")` 애노테이션 하나로 매핑이 끝납니다 (Servlet 3.0부터).
- 경로는 반드시 **`/`로 시작**. `/ch09/teamDelete`라고 쓰면 실제 주소는 컨텍스트 경로가 자동으로 붙어서 `http://localhost/myapp/ch09/teamDelete`가 됩니다.

## 3. ⚠️ 아직 안 맞는 부분 — GET 링크 ↔ doPost 서블릿

현재 `teamRead.jsp`의 버튼:
```jsp
<a href="teamDelete?num=<%=num%>">DELETE2</a>
```
`<a href>`는 **GET 요청**입니다. 그런데 서블릿엔 `doPost`만 있고 `doGet`이 없습니다.

**GET으로 요청이 오면 `HttpServlet`의 기본 `doGet()`이 실행되는데, 우리가 안 채웠으니 "405 Method Not Allowed" 에러가 납니다.** 지금 DELETE2 버튼을 누르면 이 에러를 보게 될 겁니다.

### 고치는 방법 (둘 중 하나, 아직 선택 전)

**A. 서블릿에 `doGet`도 만들기** (제일 간단)
```java
@Override
protected void doGet(HttpServletRequest request, HttpServletResponse response)
        throws ServletException, IOException {
    doPost(request, response);   // 로직 재사용
}
```

**B. 링크를 POST 폼으로 바꾸기** (더 올바른 방식 — 삭제는 상태를 바꾸는 작업이라 POST가 맞음)
```jsp
<form method="post" action="teamDelete" style="display:inline">
    <input type="hidden" name="num" value="<%=num%>">
    <input type="submit" value="DELETE2">
</form>
```

> **왜 GET으로 삭제하면 안 좋은가** — GET 요청은 브라우저가 미리 불러오거나(prefetch), 검색엔진이 링크를 따라가거나, 북마크/새로고침으로 **의도치 않게 여러 번** 일어날 수 있습니다. "데이터를 바꾸는 작업"(삭제/수정/추가)은 POST로 하는 게 원칙입니다.

## 4. 서블릿 파일 템플릿 만들기

매번 이 뼈대를 타이핑하지 않도록 IntelliJ 파일 템플릿으로 등록:

```
Ctrl+Alt+S → Editor → File and Code Templates → Templates 탭 → + → 이름: Servlet, 확장자: java
```

```java
#if (${PACKAGE_NAME} && ${PACKAGE_NAME} != "")package ${PACKAGE_NAME};#end

import jakarta.servlet.ServletException;
import jakarta.servlet.annotation.WebServlet;
import jakarta.servlet.http.HttpServlet;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

import java.io.IOException;

@WebServlet("/${NAME}")
public class ${NAME} extends HttpServlet {

    @Override
    protected void doGet(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        doPost(request, response);
    }

    @Override
    protected void doPost(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {

    }
}
```

**주의할 점**
- Velocity 지시문(`#if`, `#end`)은 **줄 맨 앞칸부터** 시작해야 함. 앞에 공백이 있으면 파싱이 깨져서 `${NAME}` 같은 게 치환 안 되고 그대로 나옴
- 반드시 **우클릭 → New → Servlet** 으로 만들어야 치환이 됨 (New → Java Class로 만들면 템플릿이 아니라서 치환 안 됨)
- 이 템플릿은 `doGet`이 `doPost`를 그대로 불러주는 구조라서, 오늘 겪은 "GET 링크인데 doPost만 있어서 405" 문제가 **새로 만드는 서블릿에서는 애초에 안 생깁니다.**

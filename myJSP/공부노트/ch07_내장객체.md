# ch07. JSP 내장객체 (Implicit Objects)

---

## 1. 내장객체란

JSP가 **`import`도 선언도 없이 바로 쓸 수 있게** 미리 만들어 둔 객체들.
JSP가 서블릿으로 변환될 때 `_jspService()` 메소드 안에 자동으로 선언됨.

| 객체 | 타입 | 역할 |
|---|---|---|
| `request` | HttpServletRequest | 클라이언트 요청 정보 (파라미터, 헤더, IP ...) |
| `response` | HttpServletResponse | 서버 → 클라이언트 응답 제어 (리다이렉트, 헤더 ...) |
| `session` | HttpSession | 사용자별 상태 유지 (로그인 등) |
| `out` | JspWriter | 브라우저로 내보내는 출력 스트림 |
| `application` | ServletContext | 웹앱 전체 공유 객체 |
| `pageContext` | PageContext | 현재 페이지 정보 |
| `config` | ServletConfig | 서블릿 설정 |
| `page` | Object (this) | 현재 JSP 페이지 자신 |
| `exception` | Throwable | 에러 페이지에서만 (`isErrorPage="true"`) |

오늘은 **request / response / session / out** 4개.

## 2. request — 요청 정보

### 2-1. 파라미터 받기 — request1

| 메소드 | 반환 | 언제 |
|---|---|---|
| `request.getParameter("name")` | `String` (1개) | text, radio, select, password |
| `request.getParameterValues("hobby")` | `String[]` (여러 개) | **checkbox** (같은 name 여러 개) |

#### request1.html — 여러 입력 타입
```html
<form method="get" action="request1.jsp">
  성명   : <input name="name" value="홍길동">
  학번   : <input name="studentNum" value="9123133">
  성별   : <input type="radio" name="gender" value="man" checked> 남자
          <input type="radio" name="gender" value="woman"> 여자
  전공   : <select name="major"> <option value="국문학과">국문학과</option> ... </select>
  취미   : <input type="checkbox" name="hobby" value="인터넷" checked> 인터넷
          <input type="checkbox" name="hobby" value="여행"> 여행
          <input type="checkbox" name="hobby" value="운동" checked> 운동
  <input type="submit" value="보내기">
</form>
```

#### request1.jsp — 받기
```jsp
<%@ page contentType="text/html; charset=UTF-8" %>
<%
    String name       = request.getParameter("name");
    String studentNum  = request.getParameter("studentNum");
    String gender      = request.getParameter("gender");        // radio: 1개
    String major       = request.getParameter("major");         // select: 1개
    String hobby[]     = request.getParameterValues("hobby");   // checkbox: 배열!
%>
name: <%=name%><br>
gender: <%=gender%><br>

hobby: <% for(int i = 0; i < hobby.length; i++){ %>
           <%=hobby[i]%>&nbsp;
       <% } %>
```

**포인트**
- 체크박스는 여러 개 체크될 수 있으니 `getParameterValues()` → `String[]`
- 배열 순회는 **`<% for %>` (스크립트릿)**. `<%= for %>` (표현식)은 **문법 에러** — 표현식은 "값 하나"만
- `hobby`가 `null`일 수 있음(하나도 체크 안 하면) → `hobby.length`에서 NPE. 실무에선 null 체크 필요

### 2-2. 요청 메타정보 — request2

```jsp
<%
    String protocol   = request.getProtocol();       // "HTTP/1.1"
    int port          = request.getServerPort();     // 80
    String remoteAddr = request.getRemoteAddr();     // 클라이언트 IP
    String method     = request.getMethod();         // "GET" / "POST"
    String uri        = request.getRequestURI();     // "/myapp/ch07/request2.jsp"
    StringBuffer url  = request.getRequestURL();     // "http://localhost/myapp/ch07/request2.jsp"
    String query      = request.getQueryString();    // "age=23&name=hong"

    String ageParam = request.getParameter("age");
%>
...
<% if (ageParam != null) { %>          <%-- 폼 제출 전엔 age가 null → 감싸야 함 --%>
    age: <%= Integer.parseInt(ageParam) %>
<% } %>

<form method="post">                    <%-- action 없으면 자기 자신 호출 --%>
    age: <input type="text" name="age" value="23">
    <input type="submit" value="SEND">
</form>
```

| 메소드 | 결과 예 |
|---|---|
| `getRequestURI()` | `/myapp/ch07/request2.jsp` (컨텍스트 포함 경로) |
| `getRequestURL()` | `http://localhost/myapp/ch07/request2.jsp` (전체 URL, StringBuffer) |
| `getQueryString()` | `age=23` (`?` 뒤 부분) |

**IPv6 문제**
- `getRemoteAddr()`가 `0:0:0:0:0:0:0:1` (IPv6 루프백)으로 나올 때
- 실행 구성 VM options에 `-Djava.net.preferIPv4Stack=true` 추가 → `127.0.0.1`로 나옴
- `jsp` 구성 → **Startup/Connection** 탭 → VM options 칸

**자주 하는 실수**
- `<input anme="age">` — `name` 오타 → 값이 전송 안 됨 → `getParameter("age")` = null
- 첫 로딩(GET, 폼 제출 전)에 `Integer.parseInt(null)` → `NumberFormatException` → `if (param != null)`로 감싸야 함

## 3. response — 응답 제어

### 3-1. sendRedirect — 다른 페이지로 이동

```jsp
<%--response1.jsp--%>
<%
    // 지정한 페이지를 Client가 다시 요청하게 만듦
    // → request 정보는 넘어가지 않음 (완전히 새 요청)
    response.sendRedirect("response2.jsp");
%>
```

- 브라우저 주소창이 `response2.jsp`로 **바뀜**
- forward와 반대: request 공유 X, URL 바뀜, 서버 왕복 2번
- 쓰기 작업(INSERT/UPDATE/DELETE) 완료 후 목록으로 보낼 때 사용 (새로고침 중복 방지)

### 3-2. setHeader — 캐시 방지

```jsp
<%--response2.jsp--%>
<%
    // 이 응답을 브라우저 캐시에 저장하지 않도록 함
    // → 로그인 페이지, 실시간 데이터, 보안 관련 페이지에 필수
    response.setHeader("Cache-Control", "no-cache, no-store, must-revalidate");
    response.setHeader("Pragma", "no-cache");         // 구형 브라우저용
    response.setDateHeader("Expires", 0);             // 캐시 만료일 0 → 항상 서버에 재요청
%>
```

**왜 필요한가**
- 캐시가 남아있으면: 로그아웃했는데 뒤로가기 하면 로그인된 화면이 그대로 보임 (보안 문제)
- 실시간 데이터: 캐시된 옛날 값이 보임
- 위 3줄로 "매번 서버에서 새로 받아라" 강제

## 4. session — 사용자별 상태 유지

### 개념
- HTTP는 요청마다 끊김 (누가 누군지 서버가 모름)
- 서버가 처음 접속한 클라이언트에게 **세션 ID**를 부여 → 이후 요청마다 그 ID로 "같은 사람" 인식
- 세션에 값을 저장해두면 여러 페이지에 걸쳐 유지됨 (로그인 상태 등)

### 흐름 — session1
```
session1.html   →   session1.jsp        →   session1_1.jsp
(로그인 폼)       (세션에 id 저장)          (세션에서 id 꺼내 사용)
```

### session1.jsp — 로그인 성공 가정, 세션에 저장
```jsp
<%
    String id = request.getParameter("id");

    String sessionId = session.getId();               // 세션 ID 조회
    session.setAttribute("idKey", id);                // 세션에 id 저장 (key-value)
    session.setMaxInactiveInterval(60 * 3);           // 유지시간 3분 (초 단위)
%>
```

### session1_1.jsp — 세션 확인 + 만료 처리
```jsp
<%
    String id = (String) session.getAttribute("idKey");   // Object 반환 → 캐스팅 필수
    int intervalTime = session.getMaxInactiveInterval();
    if (id != null) {
%>
    <b><%=id%></b>님, 좋아하는 계절: <%=request.getParameter("season")%>
    세션ID: <%=session.getId()%>
    유지시간: <%=intervalTime%>초
<% } else { %>
    세션이 만료되었거나 연결할 수 없습니다.
    <a href="session1.html">입력폼</a>
<% } %>
```

### session 메소드 정리

| 메소드 | 용도 |
|---|---|
| `session.getId()` | 세션 고유 ID (문자열) |
| `session.setAttribute("key", value)` | 값 저장 |
| `session.getAttribute("key")` | 값 꺼내기 (`Object` → 캐스팅 필요) |
| `session.removeAttribute("key")` | 값 삭제 |
| `session.setMaxInactiveInterval(초)` | 유지시간 설정 |
| `session.getMaxInactiveInterval()` | 유지시간 조회 |
| `session.invalidate()` | 세션 통째로 폐기 (로그아웃) |

### 로그인 체크 패턴 (자주 씀)
```jsp
<%
    String loginId = (String) session.getAttribute("idKey");
    if (loginId == null) {
        response.sendRedirect("login.html");   // 로그인 안 했으면 쫓아냄
        return;
    }
%>
<%-- 여기서부터 로그인한 사용자만 볼 수 있는 내용 --%>
```

## 5. out — 출력 버퍼

```jsp
<%@ page buffer="5kb" %>       <%-- 출력 버퍼 크기 지정 (기본 8kb) --%>
<%
    int total  = out.getBufferSize();   // 전체 버퍼 크기
    int remain = out.getRemaining();    // 남은 버퍼
    int used   = total - remain;        // 사용한 양
%>

<%-- 향상된 for문 --%>
<%
    String sub[] = {"Java", "JSP", "Flutter", "Spring"};
    for (String s : sub) {
        out.println(s + "<br>");
    }
%>
```

| 메소드 | 용도 |
|---|---|
| `out.println("...")` | 브라우저로 출력 (+ 줄바꿈) |
| `out.print("...")` | 브라우저로 출력 |
| `out.getBufferSize()` | 버퍼 전체 크기 |
| `out.getRemaining()` | 남은 버퍼 |

> **`out` vs `System.out`** — `out`은 브라우저로. `System.out`은 서버 콘솔(IntelliJ 하단 Run 창)로. 완전히 다름. 디버깅 메시지는 `System.out.println()`, 화면 출력은 `out.println()`.

## 6. 이렇게 써야 한다 — 요약

| 하고 싶은 것 | 코드 |
|---|---|
| 폼 값 1개 받기 | `request.getParameter("name")` |
| 체크박스 여러 값 받기 | `request.getParameterValues("hobby")` → `String[]` |
| 숫자로 변환 | `Integer.parseInt(request.getParameter("age"))` — 단, null 체크 먼저 |
| 다른 페이지로 이동 (쓰기 후) | `response.sendRedirect("list.jsp");` |
| 캐시 막기 | `response.setHeader("Cache-Control", "no-cache, no-store, must-revalidate");` |
| 로그인 정보 저장 | `session.setAttribute("idKey", id);` |
| 로그인 정보 꺼내기 | `(String) session.getAttribute("idKey")` |
| 로그아웃 | `session.invalidate();` |

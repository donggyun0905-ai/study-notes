# ch12-2. 세션 기반 로그인/로그아웃

---

## 1. 전체 흐름

```
login.jsp         →  loginProc.jsp         →  loginOK.jsp
(아이디/비번 입력)    (검증 후 세션에 저장)      (로그인 상태 화면)
                                                    │
                                                    ▼ LOG OUT 클릭
                                               logout.jsp
                                               (세션 폐기 → login.jsp로)
```

로그인 여부를 어떻게 기억하나? → **세션에 아이디를 저장해두고, 페이지마다 "세션에 아이디가 있나?"로 확인**합니다. ch07 노트의 "로그인 체크 패턴"을 실제로 적용한 예제입니다.

## 2. login.jsp — 입력 폼 + 이미 로그인했으면 건너뛰기

```jsp
<%
    String id = (String) session.getAttribute("idKey");
    if(id != null){
        // 이미 로그인된 상태
%>
<script>
    alert("로그인 되었습니다.");
    location.href = "loginOK.jsp";
</script>
<%} %>
<!-- 이 아래는 로그인 안 된 사람만 보게 됨: 입력 폼 -->
```

로그인된 사용자가 `login.jsp`를 또 열면, 입력 폼 대신 바로 `loginOK.jsp`로 튕겨냅니다.

## 3. loginProc.jsp — ⚠️ 이 파일은 "잘못된 예제"로 일부러 만든 것입니다

강사님이 주석으로 직접 `<%--잘못된 로그인 처리 방식--%>`라고 표시해두셨습니다. 어디가 잘못됐는지 정확히 짚어야 합니다.

```jsp
<%
    String id = request.getParameter("id");
    String pwd = request.getParameter("pwd");
    boolean result = false;
    if(id != null && pwd != null)      // ← 여기가 진짜 문제
        result = true;
    String msg = "로그인에 실패 하였습니다.";
    String url = "login.jsp";
    if(result){
        msg = "로그인 성공입니다.";
        url = "loginOK.jsp";
        session.setAttribute("idKey", id);
    }
%>
<script>
    alert("<%=msg%>")
    location.href="<%=url%>";
</script>
```

### 🔴 문제 1 — 비밀번호를 아예 검증하지 않음 (가장 심각한 문제)

```java
if(id != null && pwd != null)
    result = true;
```

이건 **"아이디랑 비밀번호 칸에 뭐라도 입력했으면 로그인 성공"**이라는 뜻입니다. `id`, `pwd`가 `null`이 아니기만 하면 — 즉 **아무 글자나 입력하면 무조건 로그인이 됩니다.** 실제 회원 정보와 대조하는 코드가 전혀 없습니다.

**진짜로 해야 하는 것**: DB(`tblmember` 같은 테이블)에 저장된 아이디/비밀번호와 **실제로 일치하는지** 확인해야 합니다.

```java
// 올바른 방식 예시 (MemberMgr 같은 DAO가 있다고 가정)
MemberBean member = memberMgr.getMember(id);   // DB에서 해당 id 조회
if(member != null && member.getPwd().equals(pwd)){
    result = true;
}
```
> 실무에서는 비밀번호를 DB에 평문으로 저장하지도 않습니다. `BCrypt` 같은 해시 함수로 암호화해서 저장하고, 로그인 시에도 해시값을 비교합니다. 지금 단계에서는 "아이디/비번 대조 자체가 없다"는 게 핵심 포인트입니다.

### 🟡 문제 2 — alert + location.href 방식 (부차적인 문제)

```jsp
<script>
    alert("<%=msg%>")
    location.href="<%=url%>";
</script>
```

ch06/ch07에서 배운 `response.sendRedirect()`를 안 쓰고, **화면에 스크립트만 찍어서 자바스크립트가 페이지를 이동시키는 방식**입니다.

| | alert + location.href | response.sendRedirect() |
|---|---|---|
| 동작 위치 | 브라우저(클라이언트)에서 실행 | 서버에서 바로 처리 |
| JS 꺼져 있으면 | **이동 자체가 안 됨** (먹통) | 정상 동작 |
| 속도 | 한 번 더 화면을 그렸다가 이동 (느림) | 바로 이동 |

```jsp
<%-- 더 나은 방식 --%>
<%
    if(result){
        session.setAttribute("idKey", id);
        response.sendRedirect("loginOK.jsp");
    } else {
        response.sendRedirect("login.jsp?error=1");
    }
%>
```
`alert()`로 메시지를 꼭 보여주고 싶다면, 실패 시 `login.jsp`로 파라미터(`error=1`)를 넘겨서 그 페이지에서 자바스크립트로 띄우는 게 더 흔한 방식입니다.

## 4. loginOK.jsp — 로그인 여부 확인 후 보여주기

```jsp
<%
    String id = (String) session.getAttribute("idKey");
    if(id == null){
        response.sendRedirect("login.jsp");   // 로그인 안 했으면 쫓아냄
        return;
    }
%>
<strong><%=id%></strong>님이 로그인 하셨습니다.
<a href="logout.jsp">LOG OUT</a>
```

URL을 직접 쳐서 `loginOK.jsp`로 들어오려 해도, 세션에 `idKey`가 없으면 `login.jsp`로 돌려보냅니다 — **"로그인한 사람만 볼 수 있는 페이지"의 기본 패턴**입니다 (ch07에서 배운 것과 동일).

## 5. logout.jsp — 세션 폐기

```jsp
<%
    session.invalidate();          // 세션 전체 폐기 (idKey 포함 전부 삭제)
    response.sendRedirect("login.jsp");
%>
```

`session.removeAttribute("idKey")`로 그 값 하나만 지워도 로그아웃 효과는 똑같지만, **`invalidate()`로 세션 자체를 통째로 없애는 게 더 깔끔합니다** — 로그아웃 후에 남아있으면 안 되는 다른 세션 값들(장바구니 등)도 같이 정리되기 때문입니다.

## 6. 정리 — 오늘 배운 세션 로그인의 핵심 3가지

1. **로그인 성공** → `session.setAttribute("idKey", id)` 로 "이 사람은 로그인했다"는 표시를 남김
2. **로그인 확인이 필요한 모든 페이지** → 맨 위에서 `session.getAttribute("idKey") == null`이면 `login.jsp`로 쫓아냄
3. **로그아웃** → `session.invalidate()` 로 그 표시를 통째로 지움

그리고 **`loginProc.jsp`는 이 패턴의 틀만 보여주는 예제라서 실제 비밀번호 검증이 빠져 있다는 것**을 꼭 기억하기 — 다음 수업에서 DB 조회로 교체하는 버전이 나올 가능성이 높습니다.

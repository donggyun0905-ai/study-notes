# ch15 — 공지사항 공식 구현 & 다크모드 테마 토글

어제 직접 만들어봤던 공지사항 기능이 오늘 공식 매뉴얼과 함께 도착했습니다. 원리는 같지만 세부 구현이 조금 다르고, 여기에 더해 게시판 전체에 **다크모드 토글**이 새로 적용됐습니다.

---

## 1. 공지사항 — `mode` 컬럼으로 일반글/공지글 구분

`tblBoard`에 `mode varchar(1)` 컬럼 하나만 추가해서, 값 하나로 글의 성격을 나눕니다.

| mode 값 | 의미 | 목록에서 |
|---|---|---|
| `'0'` (기본값) | 일반 게시글 | 페이징 대상, 순서대로 번호 매겨짐 |
| `'1'` | 공지글 | 페이징에서 제외, 1페이지 맨 위에 고정 |

```sql
ALTER TABLE tblBoard ADD COLUMN mode varchar(1) DEFAULT '0';
```
기존에 이미 등록돼 있던 글들은 이 ALTER문 한 줄로 전부 자동으로 `'0'`(일반글) 처리됩니다 — `DEFAULT` 값이 기존 행에도 소급 적용되기 때문입니다.

### 글쓰기 — 체크 안 하면 아예 파라미터가 없다

```jsp
<%-- post.jsp --%>
<td>공지등록</td>
<td>공지<input type="checkbox" name="mode" value="1"></td>
```
```java
// BoardMgr.insertBoard()
String mode = multi.getParameter("mode");
if(mode==null)
    mode = "0";
```
체크박스는 **선택하지 않으면 그 `name` 자체가 요청에서 빠집니다** (라디오 버튼과 다른 점). 그래서 `mode`가 `null`로 넘어오는 경우를 `"0"`으로 기본 처리해주는 코드가 꼭 필요합니다 — guestbook의 `secret` 체크박스에서 이미 본 것과 같은 패턴입니다.

### 목록 조회 — "공지 전용 조회"와 "일반 목록"을 분리

```java
// 공지글만 조회 — 페이징 없이 전체 반환
public Vector<BoardBean> getBoardNoticeList(){
    sql = "select * from tblBoard where mode = 1";
    ...
}

// 일반 목록 — 공지글은 제외
sql = "select * from tblBoard where mode !=1 order by ref desc, pos limit ?, ?";
```
**포인트는 메소드를 아예 나눴다는 것**입니다. 하나의 쿼리로 다 가져온 뒤 자바에서 걸러내는 대신, "공지만 가져오는 쿼리"와 "일반글만 가져오는 쿼리"를 SQL 단에서부터 분리했습니다. `getTotalCount()`(전체 게시물 수)도 똑같이 `mode !=1` 조건을 넣어서, **페이지 수 계산에 공지글이 섞이지 않게** 만들었습니다.

> `mode` 컬럼은 `varchar(1)`인데 비교는 `mode = 1`(따옴표 없는 숫자)로 합니다. MySQL이 문자열과 숫자를 비교할 때 자동으로 형변환을 해줘서 `'1'`이든 `1`이든 결과는 같습니다 — 다만 컬럼 타입과 비교값 타입을 맞춰 쓰는 게 원래는 더 안전한 습관입니다.

## 2. 다크모드 토글 — `<%@ include %>` 두 파일로 게시판 전체에 적용

`list.jsp`, `read.jsp`, `post.jsp`, `update.jsp`, `reply.jsp` 다섯 페이지 전부에 똑같은 두 줄이 들어갑니다.

```jsp
<%@ include file="themeHead.jsp" %>   <%-- <head> 안, Tailwind 로드 + 최초 테마 결정 --%>
...
<%@ include file="themeToggle.jsp" %> <%-- <body> 안, 우측 하단 토글 버튼 --%>
```

`ch06`에서 배운 "여러 페이지에 똑같이 들어가는 부분을 파일 하나로 빼서 `<%@ include%>`로 끼워 넣는다"는 원리를 그대로 다섯 페이지에 반복 적용한 것뿐입니다. 대신 이번엔 CSS나 자바스크립트가 페이지 하단이 아니라 **테마 결정 로직**을 담고 있습니다.

### themeHead.jsp — 화면이 그려지기 *전에* 테마부터 정해야 깜빡임이 없다

```js
tailwind.config = { darkMode: 'class' };  // <html class="dark">가 있으면 다크모드 스타일 적용
(function () {
    var theme = localStorage.getItem('theme');
    if (theme === 'dark' || (!theme && window.matchMedia('(prefers-color-scheme: dark)').matches)) {
        document.documentElement.classList.add('dark');
    }
})();
```
이 코드가 `<head>` 안, 그것도 최대한 위쪽에 있어야 하는 이유가 있습니다. **body가 그려지기 전에 다크 클래스를 먼저 붙여야**, "일단 밝은 화면으로 그렸다가 → 자바스크립트가 실행되면서 갑자기 어두워지는" 깜빡임(FOUC, Flash Of Unstyled Content)이 안 생깁니다.

- **우선순위 1**: `localStorage`에 사용자가 이전에 저장해둔 값(`'dark'`/`'light'`)이 있으면 그걸 그대로 따름
- **우선순위 2**: 저장된 값이 없으면(`!theme`) `matchMedia('(prefers-color-scheme: dark)')`로 **OS/브라우저 자체 설정**을 확인해서 맞춤

### themeToggle.jsp — 버튼 누르면 클래스 토글 + localStorage 저장

```js
function setTheme(theme) {
    if (theme === 'dark') document.documentElement.classList.add('dark');
    else document.documentElement.classList.remove('dark');
    localStorage.setItem('theme', theme);   // 다음에 들어와도 기억하도록 저장
    syncThemeButtons();                      // 버튼 자체의 활성화 표시도 갱신
}
```
`<html>` 태그에 `class="dark"`를 붙이거나 떼는 것만으로 전체 페이지 색이 바뀌는 이유는, Tailwind가 `dark:bg-slate-900`처럼 **`dark:` 접두사가 붙은 클래스를 `<html>`에 `dark` 클래스가 있을 때만 적용**하도록 미리 CSS를 만들어주기 때문입니다 (`tailwind.config = { darkMode: 'class' }`로 이 방식을 지정해둔 것).

## 3. 댓글 개수 배지 — 공지글에도 똑같이 적용

```jsp
int bcount = cmgr.getBCommentCount(num);
...
<%if(bcount>0){%>
    <span class="text-red-500">(<%=bcount%>)</span>
<%}%>
```
이 코드가 **공지 리스팅 블록과 일반 리스팅 블록 양쪽에 똑같이** 들어가 있습니다. 댓글 개수 표시는 "공지냐 아니냐"와 무관하게 게시글이라면 다 필요한 기능이라, 공지 전용 로직과 겹치지 않게 따로 유지된 것입니다.

## 4. 오늘 정리

1. **체크박스는 선택 안 하면 파라미터 자체가 사라진다** — `null` 방어 코드가 항상 필요 (guestbook의 `secret`과 동일 패턴).
2. **분류 조건이 있는 목록은 아예 조회 메소드를 분리하는 게 깔끔하다** — 하나로 가져와서 자바에서 거르기보다, "공지만", "일반만" 쿼리를 나누면 코드도 SQL도 단순해진다.
3. **화면이 그려지기 전에 결정해야 하는 값(다크모드 여부)은 `<head>`의 맨 앞쪽, 동기 스크립트로 먼저 처리**해야 깜빡임이 없다.
4. **여러 페이지 공통 UI는 `<%@ include %>`로 분리**하는 원리는 챕터가 달라져도(ch06 → ch15) 계속 재사용된다.

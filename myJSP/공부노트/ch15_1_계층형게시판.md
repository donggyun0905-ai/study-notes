# ch15 — 계층형 게시판 (목록·페이징·글읽기)

`guestbook`은 댓글이 있어도 목록 자체는 평면적으로 쭉 나열이었는데, `ch15`는 **답변글이 원글 밑에 들여쓰기로 이어지는 게시판**입니다. 오늘은 그 중 목록 페이징과 글쓰기/글읽기까지 다뤘습니다.

---

## 1. 계층 구조를 표현하는 3개의 숫자 — `ref`, `pos`, `depth`

`tblBoard` 테이블에서 이 세 컬럼이 "누가 누구의 답변인지"를 표현합니다.

| 컬럼 | 의미 |
|---|---|
| `ref` | 같은 대화 묶음(원글+답변들)을 하나로 묶는 그룹 번호 — 원글을 쓸 때 자기 자신의 `num`을 그대로 `ref`로 씀 |
| `pos` | 같은 그룹 안에서의 출력 순서 — 원글은 0, 답변이 달릴 때마다 그 아래 글들의 `pos`를 밀어서 답변이 원글 바로 밑에 오게 함 |
| `depth` | 들여쓰기 단계 — 원글은 0, 답변은 1, 답변의 답변은 2… |

```java
// BoardMgr.insertBoard() — 글쓰기(원글)는 항상 새 그룹의 시작
int ref = getMaxNum() + 1;   // 아직 num이 정해지기 전이라, "곧 만들어질 num"을 미리 계산
sql = "insert tblBoard(name, content, subject, ref, pos, depth, ...) "
    + "values(?, ?, ?, ?, 0, 0, ...)";   // pos=0, depth=0 고정 — 원글이니까
```

```jsp
<%-- list.jsp — 그룹(ref) 기준으로 묶고, 그 안에서 pos 순서로 정렬 --%>
sql = "select * from tblBoard order by ref desc, pos limit ?, ?";
```
`order by ref desc, pos`가 핵심입니다 — **최신 그룹이 먼저(`ref desc`), 같은 그룹 안에서는 `pos` 순서대로(오름차순)** 나오게 해서, 원글 바로 밑에 그 답변들이 줄줄이 붙어 보이게 만드는 정렬입니다.

```jsp
<%-- list.jsp — depth만큼 들여쓰기 --%>
<%for(int j=0;j<depth;j++){out.println("&nbsp;&nbsp;");} %>
<a href="javascript:read('<%=num%>')"><%=subject%></a>
```
화면에서는 `depth` 값만큼 공백을 반복 출력해서 답변이 오른쪽으로 밀려 보이게 하는 것뿐입니다 — 실제 트리 구조를 자바로 만드는 게 아니라, **정렬 순서(`ref`, `pos`)와 보여주는 방식(`depth`)을 분리**해서 계층을 흉내 내는 방식입니다.

> 답변 등록(`reply.jsp`)은 아직 안 만들어서 `pos`를 실제로 밀어 넣는 코드는 이번엔 안 나왔습니다 — 다음에 이어질 내용으로 보입니다.

## 2. 페이징 — "몇 번째 글부터 몇 개" 계산하기

게시물이 아무리 많아도 한 페이지엔 `numPerPage`(10개)만 보여줘야 합니다. 그러려면 "지금 이 페이지에서 보여줄 범위"를 SQL의 `LIMIT`으로 넘겨야 합니다.

```jsp
int start = (nowPage * numPerPage) - numPerPage;   // 이 페이지의 시작 위치
int cnt = numPerPage;                               // 몇 개 가져올지
```

예를 들어 `nowPage=3`, `numPerPage=10`이면 `start = 30-10 = 20` → **21번째 글부터 10개**를 가져오라는 뜻입니다 (0부터 세므로 인덱스 20).

```jsp
sql = "select * from tblBoard order by ref desc, pos limit ?, ?";
pstmt.setInt(1, start);   // 몇 번째 행부터
pstmt.setInt(2, cnt);     // 몇 개 가져올지
```

`LIMIT start, cnt` — 첫 번째 숫자가 "건너뛸 개수", 두 번째가 "가져올 개수"입니다. `ch09_3`(Team 목록)에서는 전체를 다 가져와서 화면에서만 나눴다면, 여기서는 **SQL 단에서부터 필요한 만큼만 가져온다**는 게 차이입니다 — 게시물이 수만 건이어도 매번 10개만 조회하니 훨씬 효율적입니다.

## 3. 페이지 번호를 다시 "블럭"으로 묶기

페이지가 200개면 `[1][2][3]...[200]`을 한 줄에 다 보여줄 수 없으니, **페이지를 15개씩 블럭으로 묶어서** 블럭 단위로 이동하게 만듭니다.

```java
// MUtil.ceilDivide(a, b) — 올림 나눗셈. (a + b - 1) / b
totalPage = MUtil.ceilDivide(totalRecord, numPerPage);   // 게시물 수 → 전체 페이지 수
totalBlock = MUtil.ceilDivide(totalPage, pagePerBlock);  // 전체 페이지 수 → 전체 블럭 수
nowBlock = MUtil.ceilDivide(nowPage, pagePerBlock);      // 지금 페이지가 몇 번째 블럭인지
```

일반 나눗셈(`/`)은 소수점을 버리기 때문에, 예를 들어 게시물 23개를 10개씩 보여주면 `23/10=2`가 되어 3번째 페이지(21~23번 글)가 통째로 사라집니다. **올림 나눗셈**을 써야 `(23+10-1)/10=3`으로 정확히 3페이지가 나옵니다.

```jsp
<%-- 다음/이전 블럭 이동 --%>
function sendBlock(block) {
    // 블럭 번호를 그대로 넘기지 않고, 그 블럭의 "첫 페이지 번호"로 환산해서 넘김
    document.readFrm.nowPage.value = <%=pagePerBlock%> * (block-1) + 1;
    document.readFrm.submit();
}
```
서버는 `nowPage`(현재 페이지 번호)만 알면 되기 때문에, 블럭 이동도 결국 "이 블럭의 몇 번째 페이지로 갈래?"로 변환해서 보내는 방식입니다.

## 4. 글 읽기 — 조회수 증가 + 세션에 담아두기

```jsp
<%-- read.jsp --%>
int num = MUtil.parseInt(request, "num");

mgr.upCount(num);              // 조회수 먼저 1 증가
BoardBean bean = mgr.getBoard(num);   // 그 다음 글 내용 조회

session.setAttribute("bean", bean);   // 수정/삭제/답변에서 다시 쓸 수 있게 세션에 저장
```

```java
// BoardMgr.upCount(num)
sql = "update tblBoard set count=count+1 where num = ?";
```

`count=count+1`처럼 **DB 안에서 직접 1을 더하는 방식**을 씁니다. 자바에서 값을 읽어와서 +1 하고 다시 저장하는 대신 이렇게 하면, 여러 사람이 동시에 조회해도 값을 서로 덮어써서 조회수가 씹히는 문제(guestbook에선 안 나왔지만 동시성 문제의 전형적인 예)가 안 생깁니다.

세션에 `bean`을 저장해두는 이유는, 다음에 만들 수정(`update.jsp`)·삭제·답변(`reply.jsp`) 화면에서 **"방금 읽은 그 글"** 정보를 다시 DB 조회 없이 바로 쓰기 위해서입니다 (아직 이 화면들은 만들지 않았지만, 미리 준비해둔 부분입니다).

## 5. 파일 첨부 — `ch13`에서 배운 COS 방식 그대로

```java
MultipartRequest multi = new MultipartRequest(
        request, saveFolder, MAXSIZE, ENCODING, new DefaultFileRenamePolicy());

int filesize = 0;
if(multi.getFilesystemName("filename")!=null){   // 첨부 안 했으면 null
    filename = multi.getFilesystemName("filename");
    filesize = (int) multi.getFile("filename").length();
}
```

`ch13_1_파일업로드`에서 배운 COS 라이브러리 패턴을 그대로 재사용했습니다 — 파일을 첨부 안 하면 `getFilesystemName`이 `null`을 주니 그때만 조건문으로 걸러내는 것도 동일합니다.

**본문 내용 타입(HTML/TEXT) 처리도 새로 나온 부분:**
```java
String contentType = multi.getParameter("contentType");
if(contentType.equalsIgnoreCase("TEXT"))
    content = MUtil.replace(content, "<", "&lt;");
```
글쓴이가 "TEXT"를 선택하면 `<`를 `&lt;`로 바꿔서, 본문에 `<script>` 같은 걸 적어도 진짜 태그로 실행되지 않고 그냥 글자로만 보이게 막습니다. "HTML"을 선택하면 이 치환을 안 해서 태그가 그대로 적용됩니다 — 게시판에서 글쓴이가 직접 서식을 넣고 싶을 때(HTML) vs 순수 텍스트만 남기고 싶을 때(TEXT)를 선택하게 해주는 기능입니다.

## 6. ch15b — 같은 기능, 다른 화면

`ch15b`는 `ch15`와 **완전히 같은 자바 클래스(`BoardMgr`, `BoardBean`)를 그대로 가져다 쓰면서, 화면만 Tailwind CSS로 새로 꾸민 버전**입니다.

```jsp
<%-- ch15b/list.jsp --%>
<jsp:useBean id="mgr" class="ch15.BoardMgr"/>   <%-- 패키지가 ch15b가 아니라 ch15! --%>
```

`ch14`/`ch14a`(플랫파일 버전), `99_UI확장_Tailwind와다크모드`에서 이미 봤던 것과 같은 원리 — **데이터를 가져오는 로직(Java 클래스)과 그걸 보여주는 방식(JSP 화면)은 분리할 수 있다**는 걸 반복해서 확인하는 셈입니다. 로직을 한 번만 잘 만들어두면, 화면은 필요한 만큼 다르게 여러 벌 만들 수 있습니다.

## 7. 오늘 정리

1. **계층 구조는 정렬 순서(`ref`, `pos`) + 보여주는 방식(`depth`)의 조합**으로 만든다 — 진짜 트리 자료구조를 쓰는 게 아니라 SQL 정렬과 들여쓰기 출력만으로 흉내 낸다.
2. **페이징은 `LIMIT start, cnt`로 DB에서부터 필요한 만큼만** 가져오는 게 기본 — 전체를 가져와서 화면에서 자르는 것보다 효율적.
3. **올림 나눗셈(`ceilDivide`)** 이 있어야 마지막 페이지/블럭이 안 잘린다.
4. **조회수처럼 값을 누적할 땐 `count=count+1`을 DB 안에서** 처리해야 동시 접근에도 안전하다.
5. **로직(DAO)과 화면(JSP)을 분리**해두면, 같은 기능을 여러 디자인으로 재활용할 수 있다.

DML — 데이터 조작어

ch08.sql 코드를 실행 순서대로 분석한 학습자료입니다. DEPARTMENTS 테이블(HR 스키마) 기준입니다.

01

INSERT — 컬럼 명시 vs 생략

-- 컬럼명을 명시: 순서·개수를 자유롭게, 가독성 높음(권장)
INSERT INTO DEPARTMENTS (department_id, department_name, manager_id, location_id)
VALUES (271, 'Sample_Dept', 200, 1700);

-- 컬럼명 생략: 테이블 정의 순서 그대로 모든 컬럼에 값을 채워야 함
INSERT INTO DEPARTMENTS
VALUES (272, 'Sample_Dept', 200, 1700);
실무 권장 — 컬럼 생략형은 테이블 구조가 바뀌면(컬럼 추가/순서변경) 바로 깨집니다. 운영 코드에서는 항상 컬럼명을 명시하세요.
02

트랜잭션 — COMMIT / ROLLBACK

DML(INSERT/UPDATE/DELETE)은 실행 즉시 영구 반영되지 않고 트랜잭션 상태로 대기합니다. COMMIT으로 확정하거나 ROLLBACK으로 취소할 수 있습니다.

/*
BEGIN TRANSACTION
  -- DML 여러 개 ......
COMMIT     -- 모든 변경을 영구 저장
ROLLBACK   -- 마지막 COMMIT 시점으로 전체 되돌리기
*/
학습 팁 — 실습 중 잘못된 UPDATE/DELETE를 실행했다면, COMMIT 하기 전이라면 ROLLBACK; 한 줄로 원상복구할 수 있습니다. 세션 종료나 다른 DDL 실행 시 자동 커밋되는 점도 함께 언급하면 좋습니다.
03

UPDATE — 단일 컬럼 / 다중 컬럼(서브쿼리) / NULL 설정

-- 단일/복수 컬럼을 상수로 직접 수정
update departments
set manager_id = 201, location_id = 1800
where department_id = 271;

-- 서브쿼리 결과로 여러 컬럼을 한 번에 수정 (컬럼 개수·순서 일치 필요)
update departments
set (manager_id, location_id) = (
    select manager_id, location_id
    from departments
    where department_id = 40
)
where department_name = 'Sample_Dept';

-- 특정 컬럼 값을 NULL로 비우기
update departments
set department_name = null
where department_name = 'Sample_Dept';
WHERE절 생략 금지 — UPDATE ... SET ...에서 WHERE를 빠뜨리면 테이블의 모든 행이 수정됩니다. 실행 전 반드시 같은 조건으로 SELECT를 먼저 돌려 대상 행을 확인하는 습관을 권장합니다.
04

DELETE — 조건 삭제 / 서브쿼리 조건 삭제

delete from departments
where department_name = 'Sample_Dept';

-- 서브쿼리로 삭제 대상 department_id 목록을 구해 IN으로 삭제
delete from departments
where department_id in (
    select department_id from departments
    where department_name = 'Sample_Dept'
);
DELETE도 트랜잭션 대상 — DELETE 역시 COMMIT 전까지는 되돌릴 수 있습니다(ROLLBACK 가능). 다음 챕터(ch09)의 TRUNCATE와의 차이를 꼭 짚어주세요.

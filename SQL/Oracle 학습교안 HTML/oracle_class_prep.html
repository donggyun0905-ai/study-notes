03

계정 생성 및 권한 부여

예제 학습을 위한 전용 계정을 생성하고, 접속 및 오브젝트 생성에 필요한 최소 권한을 부여합니다.

-- 예제 학습을 위한 계정 생성
CREATE USER c##hr IDENTIFIED BY 1234;

-- 접속과 리소스 사용 권한 부여
GRANT CONNECT, RESOURCE to c##hr;
주의 — 11g/12c 이상에서 c## 접두사는 CDB(컨테이너 DB) 공용 계정 규칙입니다. 접속 오류 시 alter session set "_ORACLE_SCRIPT"=true; 설정 또는 pluggable DB 여부를 먼저 확인하세요.
권한 설명 — CONNECT는 세션 접속·기본 DML 권한, RESOURCE는 테이블/시퀀스/인덱스 등 오브젝트 생성 권한을 포함합니다.
04

샘플 테이블 스키마

수업에서는 두 가지 스키마를 병행합니다 — Oracle 표준 예제인 HR 스키마와, 서브쿼리·조인 실습에 최적화된 Customers/Agents/Orders 실습 스키마입니다.

4-1. HR 스키마 (Oracle 표준 예제)

REGIONS → COUNTRIES → LOCATIONS → DEPARTMENTS → EMPLOYEES → JOB_HISTORY 순으로 참조 관계를 갖는 7개 테이블 + 1개 뷰(EMP_DETAILS_VIEW) 구조입니다.

테이블주요 컬럼설명제약
REGIONSregion_id, region_name대륙/지역PK
COUNTRIEScountry_id, country_name, region_id국가PKFK→REGIONS
LOCATIONSlocation_id, city, country_id사업장 주소PKFK→COUNTRIES
DEPARTMENTSdepartment_id, department_name, manager_id, location_id부서PKFK→LOCATIONS, EMPLOYEES
JOBSjob_id, job_title, min/max_salary직무PK
EMPLOYEESemployee_id, first/last_name, salary, manager_id, department_id직원PKFK→DEPT, JOBS, 자기참조
JOB_HISTORYemployee_id, start/end_date, job_id, department_id이력PK(복합)FK→3곳
📄 EMPLOYEES 테이블 컬럼 상세 (테이블_설명.txt)
컬럼설명
EMPLOYEE_ID직원의 고유 식별자 (Primary Key)
FIRST_NAME / LAST_NAME이름 / 성
EMAIL이메일 주소
PHONE_NUMBER전화번호
HIRE_DATE고용일
JOB_ID직책 ID (예: SA_REP = Sales Representative)
SALARY급여
COMMISSION_PCT커미션 비율 (예: 0.2 = 20%)
MANAGER_ID상사의 EMPLOYEE_ID (자기참조 FK)
DEPARTMENT_ID소속 부서 ID

DEPARTMENTS는 MANAGER_ID→EMPLOYEES, LOCATION_ID→LOCATIONS를 참조하고, LOCATIONS는 COUNTRY_ID→COUNTRIES를 참조합니다.

💾 DDL 원본 보기 — Oracle_Example_Create.sql (핵심 발췌) 
CREATE TABLE employees
    ( employee_id    NUMBER(6)
    , first_name     VARCHAR2(20)
    , last_name      VARCHAR2(25) CONSTRAINT emp_last_name_nn NOT NULL
    , email          VARCHAR2(25) CONSTRAINT emp_email_nn NOT NULL
    , phone_number   VARCHAR2(20)
    , hire_date      DATE CONSTRAINT emp_hire_date_nn NOT NULL
    , job_id         VARCHAR2(10) CONSTRAINT emp_job_nn NOT NULL
    , salary         NUMBER(8,2)
    , commission_pct NUMBER(2,2)
    , manager_id     NUMBER(6)
    , department_id  NUMBER(4)
    , CONSTRAINT emp_salary_min CHECK (salary > 0)
    , CONSTRAINT emp_email_uk UNIQUE (email)
    );

-- EMP_DETAILS_VIEW : employees + departments + jobs + locations + countries + regions 6-way join
CREATE OR REPLACE VIEW emp_details_view AS
SELECT e.employee_id, e.job_id, e.manager_id, e.department_id,
       d.location_id, l.country_id, e.first_name, e.last_name,
       e.salary, e.commission_pct, d.department_name, j.job_title,
       l.city, l.state_province, c.country_name, r.region_name
FROM employees e, departments d, jobs j, locations l, countries c, regions r
WHERE e.department_id = d.department_id
  AND d.location_id = l.location_id
  AND l.country_id = c.country_id
  AND c.region_id = r.region_id
  AND j.job_id = e.job_id
WITH READ ONLY;

전체 DDL은 Oracle_Example_Create.sql, 데이터는 Oracle_Example_Insert.sql 첨부파일 참고 (REGIONS/COUNTRIES/LOCATIONS/DEPARTMENTS/JOBS/EMPLOYEES/JOB_HISTORY 전체 INSERT + 시퀀스 3종 포함).

4-2. 실습용 스키마 — Customers / Agents / Products / Orders

서브쿼리·조인·집계 문제풀이에 특화된 4테이블 구조입니다. (table.sql, insert.sql)

테이블컬럼비고
CUSTOMERScid(PK), cname, city, discnt고객 · 할인율
AGENTSaid(PK), aname, acity, apercent판매자 · 수수료율
PRODUCTSpid(PK), pname, pcity, quantity, price상품
ORDERSordno(PK), month, cid(FK), aid(FK), pid(FK), qty, wons주문 — 3개 테이블을 모두 참조하는 팩트 테이블
💾 DDL / 샘플 데이터 미리보기 
create table orders(
 ordno char(10) primary key,
 month char(10), cid char(10), aid char(10), pid char(10),
 qty number, wons number,
 constraint fk_cid foreign key(cid) references customers(cid),
 constraint fk_aid foreign key(aid) references agents(aid),
 constraint fk_pid foreign key(pid) references products(pid)
);

-- 샘플 데이터 일부
insert into Customers values('c001','김동길','서울',10.00);
insert into Agents values('a01','김수현','부산',6);
insert into products values('p01','가위','대전',111400,500);
insert into orders values('1011','1월','c001','a01','p01',1000,450000);
활용 팁 — HR 스키마는 실무형 조인·집계(부서/직원/급여) 문제에, Customers/Agents/Orders 스키마는 서브쿼리·상관 서브쿼리·집합 연산자 실습(연습문제/실전문제)에 주로 사용됩니다.

👀 ch06 JOIN 예제 미리보기 
-- 전통적 조인 (WHERE 절)
select first_name, e.department_id, d.department_name
from employees e, departments d
where e.department_id = d.department_id;

-- ANSI JOIN
select first_name, e.department_id, d.department_name
from employees join departments d
         on e.department_id = d.department_id;

-- Sales 부서 근무 직원의 job_title 조회 (3-way join)
select e.first_name, j.job_title
from employees e join departments d on e.department_id = d.department_id
                join jobs j on e.job_id = j.job_id;

📝 실전문제 샘플 (16문항 中 발췌)

1번 ANSI 조인문을 이용하여 '3월'에 제품을 주문받은 판매자명(aname), 주문번호(ordno)와 주문한 고객명(cname)을 구하시오.

6번 '대전'에 거주하는 최소 한 명 이상의 고객이 '경주'에 거주하는 판매자(aid)에게 주문했을 경우, 이 제품의 이름(pname)을 구하시오. — 상관 서브쿼리 활용

9번 고객 'c006'이 주문한 제품(pid)을 모두 판매하는 판매자의 이름(aname)을 구하시오. — 집합 포함(division) 문제

13번 '서울' 또는 '충주'에 거주하는 고객들이 한 개의 공통된 제품(pid)을 주문한 경우, 주문받은 판매자의 판매번호(aid)를 검색하시오.

-- 9번 힌트: c006이 주문한 제품 = p01(가위), p07(싸인펜) → a01(김수현)
select pid, aid from orders where pid in ('p01', 'p07') order by 1;
select distinct pid from orders where cid = 'c006';
수업 진행 제안 — ch03~ch06(SELECT/함수/조인)까지는 HR 스키마로, ch07 서브쿼리부터는 Customers/Agents/Orders 스키마의 연습·실전문제로 전환하여 난이도를 단계적으로 올리는 구성을 권장합니다.
